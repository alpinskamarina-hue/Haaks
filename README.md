# ZZP Paspoort

Прототип личного кабинета для строителей ZZP в Нидерландах. Рабочий загружает свои документы (выписку KvK, сертификат VCA, полис AVB/CAR), ИИ сам считывает из них номера и сроки действия, а рабочий получает одну ссылку и QR‑код. Заказчик открывает ссылку и видит все документы на нидерландском (или английском) со ссылками на официальные реестры для проверки.

Интерфейс кабинета: польский, румынский, украинский, русский, английский, нидерландский. Переводы сделаны с помощью ИИ, перед запуском их должен вычитать носитель языка.

## Что умеет

Все сервисы собраны в один кабинет Haaks: на компьютере меню слева, на телефоне панель вкладок снизу. Разделы: Главная, Поиск заказчиков, Предложения, Заказы и чеки, Счета, Паспорт. Главная показывает новых заказчиков, предложения без ответа, неоплаченные счета, НДС за квартал, текущий заказ и готовность паспорта, плюс быстрые кнопки «Фото чека», «Добавить объявление», «Новое предложение», «Новый счёт».

### Поиск заказчиков

- Рабочий вставляет текст или скриншот объявления из Facebook, WhatsApp, Telegram или Marktplaats. Claude определяет, заказ ли это, профессию, город, сроки и контакт, ставит оценку, насколько заказ подходит (по профессии и регионам из профиля), пересказывает на языке рабочего и пишет ответ на нидерландском со ссылкой на ZZP‑паспорт.
- Ответ рабочий отправляет сам: копирует текст, открывает WhatsApp (если в объявлении есть номер 06…) или email. Haaks не пишет людям от имени рабочего.
- Кнопка «Сделать предложение» превращает объявление в заказ и открывает форму коммерческого предложения.
- Автоматические источники (Telegram‑группы, omgevingsvergunningen, email‑уведомления) пока показаны как следующий шаг; таблица `leads` уже хранит поле `source` для них. План: `plans/ai-agent-poisk-zakazov.md` в файлах проекта.

- Вход по ссылке на email, без пароля и SMS.
- Загрузка документа фото с камеры или PDF (до 8 МБ). Файлы лежат в закрытом хранилище.
- Чтение документа через Claude API: номер, даты выдачи и окончания, страховщик, сумма покрытия, краткое пояснение и предупреждения на языке рабочего. Пустые поля профиля (название фирмы, KvK, btw) заполняются из выписки KvK.
- Ручное исправление номера и дат, если ИИ ошибся.
- Индикатор «Готов к стройке»: KvK‑номер, btw‑id, выписка KvK, VCA, AVB. Для недостающего пункта есть подсказка, где его взять.
- Метки «Истёк», «Скоро истекает» (меньше 30 дней) и «Выписка KvK старше 3 месяцев».
- Публичная страница паспорта `/p/<токен>`: данные фирмы, документы со статусами, ссылки на поиск KvK, VIES и реестр VCA, просмотр файлов по временным ссылкам на 10 минут. Страница закрыта от поисковиков.
- Рабочий выбирает, какие документы показывать, может выключить паспорт или сделать новую ссылку (старая перестаёт работать). Ведётся счётчик просмотров.

### Заказы и чеки

- Раздел «Заказы»: заказчик, адрес объекта, статус. Один заказ отмечается как текущий, и новые чеки по умолчанию идут в него.
- Чек можно сфотографировать камерой прямо в магазине или загрузить готовые файлы (фото из галереи или PDF‑счёт, сразу несколько).
- Claude читает чек: магазин, дату, номер, позиции, сумму с НДС и без, ставки НДС. Если чек анонимный и дороже 100 €, ставит пометку, что для вычета НДС нужен счёт на фирму.
- Чек без заказа попадает в «Не разобрано», его можно перенести в любой заказ. Суммы можно исправить вручную.
- По каждому заказу видны расходы на материалы с НДС и без, а на странице заказов — уплаченный НДС за текущий квартал.

### Коммерческие предложения (offertes)

- Рабочий описывает работу на своём языке, фотографирует объект и указывает ставку в час и НДС.
- Claude составляет черновик на нидерландском: позиции работы (часы по ставке рабочего), материалы с примерными ценами строительных магазинов и прочие расходы. Отдельно, на языке рабочего, пишет допущения и что уточнить у заказчика.
- Рабочий правит позиции, суммы считаются сразу: без НДС, НДС по ставкам, итого. Номер вида OFF-2026-001, срок действия 30 дней, стандартные условия.
- Заказчик получает ссылку `/q/<token>`: предложение на нидерландском с реквизитами (KvK, btw-id, адрес), можно распечатать или сохранить в PDF и нажать «Akkoord» с указанием имени. Рабочий видит, кто и когда согласился.
- Предложение привязывается к заказу и видно на его странице.
- Цены от ИИ — только черновик: рабочий обязан проверить их перед отправкой.

### Счета (facturen)

- Реквизиты рабочего (название, адрес, KvK, btw‑id, IBAN, телефон, email) подставляются из профиля. Если чего‑то не хватает, в счёте видно предупреждение.
- Счёт создаётся из заказа (можно сразу добавить материалы из его чеков) или из принятого коммерческого предложения. Данные заказчика (адрес, KvK, btw‑id) и режим НДС берутся из прошлого счёта этому заказчику.
- Три режима НДС:
  - **с НДС** 21% / 9% по строкам;
  - **btw verlegd** — для субподряда в строительстве: НДС не начисляется, в счёте обязательно btw‑номер заказчика и пометка о verleggingsregeling;
  - **KOR** — без НДС для тех, кто зарегистрирован в kleineondernemersregeling.
- Номер идёт по порядку внутри года и подстраивается под формат рабочего (после 2026-09 будет 2026-10). Номер можно поменять вручную.
- Заказчик получает ссылку `/f/<token>` со счётом на нидерландском. PDF делается через «Печать → Сохранить как PDF». Статусы: черновик, отправлен, оплачен.

Чего пока нет: подписки и оплаты, напоминаний о сроках, водяных знаков на файлах, проверки через KvK API.

## Запуск

1. Создайте проект на [supabase.com](https://supabase.com) в регионе ЕС (например, Frankfurt).
2. Откройте в Supabase **SQL Editor** и выполните по очереди [`supabase/schema.sql`](supabase/schema.sql), [`supabase/002_orders_receipts.sql`](supabase/002_orders_receipts.sql), [`supabase/003_quotes.sql`](supabase/003_quotes.sql), [`supabase/004_invoices.sql`](supabase/004_invoices.sql) и [`supabase/005_leads.sql`](supabase/005_leads.sql). Они создадут таблицы, правила доступа и закрытое хранилище `documents`.
3. В **Authentication → URL Configuration** укажите адрес сайта (Site URL) и добавьте `https://<ваш-сайт>/auth/callback` в Redirect URLs. Для локального запуска: `http://localhost:3000/auth/callback`.
4. Скопируйте `.env.example` в `.env.local` и заполните ключи из **Project Settings → API** и ключ Claude API из [console.anthropic.com](https://console.anthropic.com). Без ключа Claude документы сохраняются, но не читаются автоматически.
5. Запустите:

```bash
npm install
npm run dev
```

Откройте http://localhost:3000.

Для публикации подойдёт Vercel: импортируйте репозиторий, добавьте те же переменные окружения и укажите `NEXT_PUBLIC_SITE_URL` с адресом сайта.

## Устройство

- `src/app/page.tsx` — вход.
- `src/app/dashboard/layout.tsx` — общий каркас кабинета (меню), `src/app/dashboard/page.tsx` — главная.
- `src/app/dashboard/passport/page.tsx` — паспорт и документы.
- `src/app/dashboard/leads/` и `src/app/leads-actions.ts` — поиск заказчиков.
- `src/app/p/[token]/page.tsx` — публичный паспорт для заказчика.
- `src/app/dashboard/orders/` — заказы и чеки.
- `src/app/actions.ts` — серверные действия: профиль, документы, паспорт.
- `src/app/orders-actions.ts` — серверные действия: заказы и чеки.
- `src/app/dashboard/quotes/` — коммерческие предложения, `src/app/quotes-actions.ts` — их серверные действия.
- `src/app/q/[token]/page.tsx` — предложение для заказчика с кнопкой «Akkoord».
- `src/app/dashboard/invoices/` и `src/app/invoices-actions.ts` — счета, `src/app/f/[token]/page.tsx` — счёт для заказчика и PDF.
- `src/lib/extract.ts` — чтение документов и чеков и черновики предложений через Claude API (модель задаётся `CLAUDE_MODEL`).
- `src/lib/documents.ts` — типы документов, статусы, требования для стройки.
- `src/lib/i18n.ts` — тексты интерфейса.
- `supabase/schema.sql` — база данных.

## Персональные данные

Паспорт и ID‑карту не запрашиваем, BSN не храним. Каждый рабочий через правила базы видит только свои записи и файлы. Публичная страница читает данные на сервере и выдаёт файлы только по временным ссылкам. Перед запуском с реальными пользователями нужны политика конфиденциальности и договор обработки данных с Supabase и Anthropic.
